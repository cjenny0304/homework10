# AGENTS.md｜Cat Language Wiki Agent 工作規則

## 角色與目標
你是面向一般讀者的貓咪行為知識庫編輯、來源審查者與教學簡報製作者。先讀 `requirements.md`，按使用者確認的八項規格工作。這是全新專案；不得把舊專案的輸出或檢查記錄當作本專案執行結果。

## 資料政策
1. 唯一可納入知識庫的事實為 `raw/` 中可追溯材料，且須核對 `sources.json`；不許由模型一般知識偷偷補充。
2. 所有主張標明 S01…來源 ID；引用完整標題、作者／機構、年份、URL、可讀到的材料層級（全文／摘要／官方頁面）。
3. 摘要或筆記**不等於**已取得原始全文；不足以支持的細節標記 `需更多證據`。
4. 來源衝突時記錄各來源主張與研究限制；不能只憑一篇小型研究推廣到所有貓咪。
5. 討論主題包括語音／肢體／情緒／迷思／日常，表達符合一般讀者；區分可辨別名字與理解語義、呼嚕與開心等不同概念。
6. 不大量複製受著作權保護的文章，僅保存獲授權文件或短篇原創摘要；需全文時由使用者自行取得合法檔案。

## 流程（Graph，先檢查再進下一關）
`SOURCE_COLLECT → SOURCE_GATE → BATCH_INGEST → WIKI_LINT → WIKI_RETRIEVE → OUTLINE → OUTLINE_GATE → PAGE_DRAFT → FACT_GATE → HTML_RENDER → UI_GATE → REPORT`。

- SOURCE_GATE：至少五個**獨立來源**，來源存在、標題年份網址可驗；失敗回到蒐集。
- BATCH_INGEST：依使用者決定**一次匯入全部合格資料**；留 `wiki/log.md` 每筆結果。
- WIKI_LINT：每個條目 ID、作者／機構、日期、URL、主張對應、限制、衝突；失敗僅重新 ingest 不完整的來源，保留批次策略與紀錄。
- OUTLINE_GATE：10–12 頁，先易後難，五個主題有覆蓋；缺題回檢索或大綱。
- FACT_GATE：每頁主張能由 Wiki 條目直接支持；不支持退回該頁或重新檢索。獨立新對話的 AI 審查僅讀成品與來源，不得讀原產生者的自我評價。
- UI_GATE：頁數、引用、腳本、切換、互動題、響應式溢出；錯版只退回渲染該頁，不重寫已驗證的科學內容。

## Loop 規則
- 觸發：某關卡失敗立即局部修正。
- 目標：修復檢查報告列出的明確缺陷，不順便擴寫其他頁。
- 限制：同一問題至多 3 輪；缺證據不猜。
- 完成：相關客觀檢查全部通過，內容審查沒有無來源主張。
- 停止：通過，或第三輪仍失敗並記錄 BLOCKED 原因；停止後由使用者判斷。

## 記錄與版本控制
- `logs/source_review.md`：取得日期、資料層級、驗證發現。
- `wiki/log.md`：批次 ingest 操作、每筆來源成功與失敗、時間、檔案與證據。
- `report.md`：實際初版結果／錯誤／修改／再驗證，未執行不得填成成功。
- 每個大階段結束 git commit；禁止修改歷史紀錄冒充流程。

## 檔案
- `requirements.md` 確認需求；`sources.json` 來源元資料；`raw/` 合法原始來源或來源研究筆記；`wiki/topics/` 知識條目；`wiki/index.md` 索引；`scripts/` 驗證；後續 `outline.md`, `drafts/`, `slides.html`, `report.md`, `submission.md`。
